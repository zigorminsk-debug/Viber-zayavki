# Заявки в Viber — Android-приложение (APK)

Приложение собирает заявки через настраиваемую форму и отправляет их в Viber:
автоматически через **Viber REST API** (Public Account / Broadcast), через **webhook**
(n8n / Make / свой сервер) или открывает **приложение Viber** с готовым текстом
заявки (deep link) — для групп и чатов, куда API писать не может.

- Готовый APK: `dist/viberlead-release.apk` (копия в корне рабочей папки: `ViberLead-v1.1-release.apk`)
- Версия: **2.27** (versionCode 39) — база организаций, мультивыбор, Яндекс Навигатор,
  нормализация телефонов, все поля в сообщении, запоминание контакта,
  внешняя база организаций (переживает переустановку), заголовок «Заявка <компания>»
- Резервная копия исходников: `../viber-lead-src-v2.27.tar.gz`
- Пакет: `by.viberlead.app`, minSdk 21 (Android 5.0), targetSdk 34
- Подпись: release-keystore `keystore/viberlead.jks` (v1+v2+v3 схемы)
- Размер ~180 КБ, внешних зависимостей нет (чистая Java + Android SDK)
- Разрешения: только `INTERNET` и `ACCESS_NETWORK_STATE`

---

## 1. Установка APK

1. Скопируйте `ViberLead-v1.0-release.apk` на телефон.
2. Откройте файл → «Установить» (разрешите установку из этого источника).
   На старых Android: Настройки → Безопасность → «Неизвестные источники».
3. Запустите «Заявки в Viber».

Проверка подписи на компьютере:
```bash
$ANDROID_HOME/build-tools/34.0.0/apksigner verify --print-certs ViberLead-v1.0-release.apk
```

## 1.1. Что нового в версии 1.1

1. **База организаций (SQLite)** — кнопка **«Орг-ции»** на главном экране.
   Поля формы нового типа `org` (живой поиск по мере ввода, подсказки в две строки:
   название + адрес/контакт/телефон) и автоподстановка связанных полей при выборе
   или при потере фокуса (дозаполняются только пустые — ручные правки не затираются).
   База **пополняется сама при каждой отправленной заявке** (upsert по названию,
   пустые значения не перезаписывают сохранённые). Ручное управление: добавить,
   изменить, удалить, построить маршрут.
2. **Поле «Заявка» вместо «Услуга / товар»** — тип `multiselect`: выпадающий список
   с чекбоксами, можно отметить несколько пунктов (Заправка, Ремонт, Сброс ошибок,
   Диагностика — список меняется в конфиге). В сообщение значения попадают через запятую.
3. **Адрес + Яндекс Навигатор**: у поля типа `address` справа кнопка **🧭**
   (долгое нажатие на самом адресе работает так же). Навигатор строит маршрут по
   координатам, поэтому адрес геокодируется: сначала кэш координат в базе организации
   (мгновенно), иначе разовый запрос OSM Nominatim с сохранением координат в базу;
   при неудаче — Яндекс.Карты в режиме маршрута, крайний резерв — системный выбор карт.
4. **Почему правки полей раньше «не появлялись» и что исправлено:**
   - конфигурация полей из assets применялась только при самом первом запуске;
     теперь у неё есть **версия**: при обновлении приложения новые встроенные поля
     применяются принудительно (versionCode 2 → конфиг v2);
   - в настройках появилась **живая валидация JSON**: под редактором сразу видно
     «✅ JSON корректен · полей: N · …» или конкретную ошибку — ошибочный конфиг
     больше не сохраняется молча;
   - при ошибке JSON экран **не закрывается** и не показывает ложное «сохранено»;
   - при выходе кнопкой «Назад» с несохранёнными правками спрашивается
     «Сохранить / Выйти без сохранения»;
   - после сохранения toast честно сообщает, сколько полей теперь на форме.

## 1.2. Что нового в версии 1.2

1. **Любой телефон → международный формат.** Поля типа `phone` нормализуются
   при потере фокуса и при отправке: `029 123-45-67`, `8 029 …`, `29 …`,
   `37529…`, `00375…` → `+375291234567`; `8 916 …` / `7 916 …` → `+7916…`.
   Код страны по умолчанию настраивается: **«Настройки → Телефоны → Код страны»**
   (без «+», по умолчанию 375). Нераспознанный короткий ввод не теряется —
   остаётся как есть. Телефоны в базе организаций и в deep link тоже хранятся
   нормализованными.
2. **Ссылка на точку Яндекс.Карт/Навигатора в заявке.** В сообщение добавлен
   плейсхолдер **`{address_link}`** (строка «🗺 Точка: …» в шаблоне по умолчанию):
   - координаты адреса берутся из кэша базы организации (мгновенно) или
     геокодируются один раз при отправке (OSM Nominatim, сокращения вида «пр.»
     раскрываются автоматически) и кэшируются;
   - ссылка вида `https://yandex.ru/maps/?ll=27.559,53.903&pt=27.559,53.903&z=17` —
     тап по ней открывает точку в Яндекс.Картах/Навигаторе с маршрутом от текущей
     позиции получателя;
   - если координаты получить не удалось (нет сети), подставляется ссылка-поиск
     `https://yandex.ru/maps/?text=…` — точка находится в один тап;
   - в webhook-payload ключ `address_link` приходит внутри `fields`.

## 1.3. Что нового в версии 1.3

1. **Нормализация телефона стала мгновенной**: раньше международный формат
   появлялся только после потери фокуса/отправки, из-за чего вставленный номер

     больше не попадают в форму);
   - при записи в базу (`upsert`) — база всегда хранит международный формат;
   - **миграция базы v2**: уже сохранённые организации приводятся к `+…` при обновлении.
3. Мелочи: превью шаблона показывает пример ссылки на точку; исправлена сборка
   после восстановления окружения (контекст в OrgDb, экранирование regex).

## 1.4. Что нового в версии 1.4

**Телефон (и любое другое значение) больше не может «потеряться» из заявки.**

Причина прежней потери: если ключ поля в конфиге не совпадал с плейсхолдером
шаблона (например, поле переименовали в `phone`, а шаблон ждал `{org_phone}`),
строка «Телефон: …» считалась пустой и молча удалялась из сообщения.

Теперь двойная защита в `MessageBuilder`:
1. **Нечёткое сопоставление телефонных плейсхолдеров**: `{org_phone}`, `{phone}`,
   `{telefon}`, `{тел}` подставят значение любого телефонного поля формы
   (и наоборот);
2. **Контроль полноты после сборки**: каждое непустое значение поля, которого нет
   в итоговом тексте, дописывается строкой «📞 Метка: значение» (для остальных
   полей — «🔹 Метка: значение»). Заявка всегда содержит все введённые данные,
   даже при рассинхроне конфига и шаблона.

То же действует в «Предпросмотре» на экране настроек.

## 1.5. Что нового в версии 1.5

1. **Нормализация телефона больше не зависит от конфига**: поле приводится к
   `+375…`, если само его содержимое похоже на телефон (только цифры с
   допустимыми `+ ( ) -` пробелами, 9–15 цифр) — даже если в JSON-конфиге у поля
   забыт `type=phone` или «телефонный» ключ. Работает при вводе, вставке,
   потере фокуса и чтении значения в заявку.
2. **Защита от дубликатов ключей в конфиге полей**: если два поля имеют один
   ключ, раньше значение «съедалось» (в заявку попадало пустое поле). Теперь
   дубликат скрывается, а на главном экране выводится предупреждение
   «⚠️ В конфиге полей дублируются ключи: …».
3. **Долгое нажатие на «Отправить» = предпросмотр ТОЧНОГО текста заявки**
   с текущими значениями формы (и ссылкой на точку, если координаты уже в кэше).
   Удобно проверить, что именно уйдёт в Viber, и скопировать при необходимости.

## 1.6. Что нового в версии 1.6

По скриншоту из Viber: строка «👤 Контакт:» ушла пустой, а строки с телефоном
не было вовсе. Причина — на устройстве шаблон сообщения не содержит плейсхолдера
телефона, а страховка v1.4/1.5 пропускала значение (короткое «909» совпадало
подстрокой внутри адреса «Дзержинского 104 909»), плюс пустые строки-ярлыки не
отсекались. Исправлено:

1. **Пустые строки больше не отправляются**: если все плейсхолдеры строки
   шаблона оказались пустыми, вся строка удаляется из текста заявки
   («👤 Контакт:» без значения исчезнет, а не уйдёт пустой).
2. **Страховка от «совпадения подстрокой»**: значение поля считается уже
   присутствующим в тексте только как пара «Ярлык: значение» либо если оно
   длиннее 7 символов — короткий номер «909» внутри адреса больше не мешает
   добавить телефон отдельной строкой.
3. **Финальная гарантия телефона (`ensurePhone`)**: после сборки текста
   приложение ищет первое телефонное поле (по типу или «телефонному» значению,
   кроме полей типа «число»), приводит номер к международному формату
   (+375…) и, если ни нормализованного, ни исходного номера в тексте нет,
   дописывает строку «📞 Ярлык: +375…». Телефон теперь попадает в заявку при
   любом шаблоне и любом конфиге полей устройства.

## 1.7. Что нового в версии 1.7

Требование: **в сообщение должны попасть все поля заявки**. Гарантировано:

1. **Точный учёт отрисовки**: при подстановке плейсхолдеров шаблон запоминает,
   какие ключи полей РЕАЛЬНО попали в текст (включая нечёткое сопоставление
   телефонных ключей `{phone}` ↔ `{org_phone}`).
2. **Все незаполненные плейсхолдеры → строка дописывается**: каждое непустое
   значение поля, которого нет в тексте (ни через свой плейсхолдер, ни парой
   «Метка: значение»), дописывается отдельной строкой «🔹 Метка: значение»
   (телефон — «📞»). Убрана старая эвристика «значение найдено подстрокой
   7+ символов» — из-за неё организация «Дзержинского» могла «раствориться»
   внутри адреса «Дзержинского 104 909» и не попасть в заявку.
3. **Ссылка на точку Яндекса** (`{address_link}`) тоже дописывается, если её
   нет в шаблоне, а координаты известны.
4. **Без дублей**: поле, уже отрисованное шаблоном, второй раз не добавляется
   (проверено JVM-тестом: 20/20, включая шаблон только с `{company}` — все
   6 полей попадают в текст ровно по одному разу).

1. **Отправка без обрезки текста**: вместо deep link `viber://forward?text=…`

## 2.1. Что нового в версии 2.1

1. **Форма чистая при открытии**: при каждом открытии главного экрана поля
   формы создаются пустыми (старые значения прошлой заявки не остаются).

2. **Запомненный получатель Viber**: в «Настройках» (раздел Deep link)
   указывается получатель — ссылка на чат/группу (`viber://pa?chatURI=…`,
   `viber://contact?number=+375…`, ссылка-приглашение группы) или ID/телефон
   для API. Включён режим «⚡ Отправлять сразу в запомненный чат» (по умолчанию
   вкл): заявка открывается сразу в нужном чате с готовым текстом, без экрана
   выбора получателя. Получатель меняется в настройках в любой момент.
3. **Полностью фоновая отправка** (вообще без открытия Viber) — режим API с
   токеном: заявка уходит серверу Viber в фоне, экран выбора не появляется
   вовсе. Без токена Viber технически не принимает фоновые сообщения в обычные
   группы, поэтому минимум действий = «открылся нужный чат с текстом → нажать
   отправить».

## 2.1.1. Исправление падения настроек

Экран «Настройки» падал с ClassCastException: переменная `tvDbStatus`
(статус базы организаций) по ошибке была объявлена как `EditText`, хотя в
разметке это `TextView`. Объявление исправлено, `refreshDbStatus()` дополнительно
обёрнут в try/catch, чтобы статус базы никогда не мог уронить экран.
Чекбокс «⚡ Отправлять сразу в запомненный чат» перемещён в свой раздел
«Deep link» (рядом с полем получателя).

## 2.2. Ссылка-приглашение в группу больше не «глотает» заявку

Ссылки-приглашения Viber (`https://invite.viber.com/…`, `https://vb.me/…`)
открывают группу, но **не умеют нести текст сообщения** — заявка терялась.
Теперь приложение различает ссылки:

* **deep link с текстом** (`viber://pa?chatURI=…`, `viber://contact?number=…`,
  `viber://forward?text=…`) — как раньше: чат открывается с готовым текстом;
* **http(s)-ссылка (приглашение в группу)** — группа открывается, а текст
  заявки **копируется в буфер обмена**, и подсказка говорит: в чате удержать
  поле ввода → «Вставить» → отправить. Текст больше не теряется молча.

Полностью фоновая отправка в обычную группу Viber по-прежнему невозможна без
токена API (ограничение Viber): с токеном заявка уходит в фоне, без токена —
минимум действий: открыть нужный чат + вставить/отправить.

## 2.3. Понятный диалог для отправки в группу

Обрезанный тост v2.2 не объяснял, что делать дальше. Теперь при получателе-
группе (ссылка-приглашение) приложение показывает диалог «Отправка в группу
Viber» с двумя явными кнопками:

В диалоге честно написано: полностью фоновая отправка в обычную группу Viber
возможна только с токеном Viber API (ограничение Viber, не приложения).

## 2.6. Геокодинг только по Минску и Минскому району

* цепочка запросов Nominatim: «адрес, Минск» → «адрес (с раскрытыми
  сокращениями), Минск» → «…, Минский район» → общие варианты;
* область поиска ограничена рамкой региона (`viewbox` + `bounded=1`);
* результат дополнительно проверяется по рамке 53.55–54.25 с.ш. /

Проверено на живом Nominatim: «проспект Дзержинского 104, Минск» → точка в
Минске; «Центральная 5, Колодищи, Минский район» → точка в Колодищах;
«Крещатик 1, Минск» → пусто (без ложных точек).

## 2.7. Точка больше не уезжает за 900 км: чистка старого кэша координат

Причина уезжавшей точки: координаты, закэшированные в базе организаций ДО
v2.6 (когда геокодер искал по всему миру), использовались ссылкой на точку и
маршрутом без повторного поиска. Исправлено:

1. **Чистка кэша при старте**: все сохранённые координаты вне рамки Минска и
   Минского района сбрасываются в 0 (тост «🧭 Сброшено старых точек…: N»),
   при следующей заявке координаты ищутся заново — уже по правилам v2.6.
2. **Проверка кэша при каждом использовании**: ссылка на точку, предпросмотр и
   маршрут используют кэш только если точка внутри региона; иначе адрес
   геокодится заново (поиск только Минск + Минский район).
3. Фильтр v2.6 сохранён: запросы ограничены рамкой региона, результат вне
   рамки отбрасывается.

## 2.10. Сохранённая группа открывается сразу, окно контактов не появляется

В v2.9 способом по умолчанию было «окно Viber с готовым текстом» — из-за этого
при сохранённой ссылке-приглашении всё равно открывалось окно выбора контактов
Viber. В v2.10:

* способ по умолчанию = **«Авто»**: если в «Настройках → Получатель» сохранена
  ссылка-приглашение в группу, нажатие «Отправить» **сразу открывает саму
  группу**, текст заявки уже скопирован (удержать поле ввода → «Вставить» →
  отправить). Окно контактов Viber не показывается;
* если ссылки нет — открывается окно Viber с готовым текстом (выбор чата);
* явные способы «1» и «2» остались в «Настройках → Deep link»;
* миграция: у устройств, где способ «1» сохранился как дефолт v2.9 при
  сохранённой http-ссылке получателя, способ переключается на «2» автоматически.

## 2.11. Окно контактов Viber больше не появляется при сохранённой группе

Причина повтора: способ «1» (окно Viber с выбором контактов) мог сохраниться
ещё старыми версиями (кнопка «1. Отправить через Viber» в прежнем диалоге), а
миграция v2.10 проверяла ссылку-приглашение только в поле «ID получателя»,
тогда как она сохранена в «Получатель: ссылка на чат» (chat_uri).

* Миграция v2.11: способ «1» переключается на «2» (открыть сохранённую группу),
  если http-ссылка сохранена в любом из двух полей (receiver или chat_uri).
* Даже при выключенном переключателе «⚡ Отправлять сразу…» приложение не
  открывает окно контактов молча: если сохранена ссылка-приглашение,
  показывается явный выбор из двух способов.

## 2.12. Авто-вставка заявки в чат Viber

Группа открывалась, но текст приходилось вставлять вручную. Теперь в приложении
есть служба специальных возможностей `AutoPasteService`:

* после нажатия «Отправить» служба «взводится» на 15 секунд;
* когда открывается окно Viber (только `com.viber.voip`), служба находит поле
  ввода сообщения и сама вставляет текст заявки (ACTION_SET_TEXT);
* при отмеченной опции «Авто-нажатие кнопки „Отправить“» (включена по
  умолчанию) служба сама нажимает кнопку отправки в Viber — заявка уходит
  без единого касания после нажатия «Отправить» в форме;
* без включённой службы поведение прежнее: текст в буфере обмена + подсказка;
* включение: «Настройки → Авто-вставка в Viber → Включить авто-вставку»
  (открывает спецвозможности Android, там разрешить службу ViberLead).
  Статус службы виден прямо в настройках.

Безопасность: служба реагирует только 15 секунд после взвода и только на окна
Viber; в остальное время ничего не трогает.

## 2.20. Лайт-версия + голосовой ввод во всех полях

свободным текстом: организация, адрес (между полем и компасом),
контактное лицо, телефон, заявка-текст, комментарий и любые поля конфига.
Без микрофона остаются только поля, где ввод не текст: дата (календарь),
мультивыбор (список отметок), выпадающий список, чекбокс.
Надиктованный текст дописывается в своё поле; телефон затем нормализуется.

## 2.22. Диктовка телефона без краша + телефон только цифрами

* Краш «setSpan ends beyond length» при диктовке телефона устранён:
  нормализатор телефона укорачивает текст внутри setText, а курсор ставился
  на старую длину. Теперь позиция курсора берётся из фактической длины
  текста после всех наблюдателей.
* Поле телефона принимает ТОЛЬКО цифры и «+»: буквы (с клавиатуры или из
  диктовки) удаляются мгновенно; надиктованная фраза перед вставкой
  предварительно очищается до цифр и «+».
* Рабочее пространство очищено: удалены все старые APK (v1.2–v2.21)
  и временные файлы, остались только сборки текущей версии.

## 2.23. Короткая ссылка «Точка»

Заявка занимала пол-экрана из-за ссылки точки: percent-кодированный адрес
(`...%D1%83%D0%BB...`) в 8 строк. Теперь:
* адрес перед геокодингом и построением ссылки очищается от внутренностей
  («1 эт», «каб. 5», «офис 3») и мусорных пробелов; если город не указан,
  добавляется «, Минск» — геокодинг стал попадать чаще, и ссылка становится
  короткой координатной `?ll=…&pt=…&z=17` (~2 строки);
* если координаты всё же не нашлись, резервная ссылка больше не кодирует
  адрес в percent-вид: человекочитаемая
  `https://yandex.ru/maps/?text=ул.+Казинца+83а,+Минск` (1–2 строки);
* координатная ссылка тоже ужата (5 знаков после запятой вместо 6).
Полный адрес с этажом остаётся в строке «Адрес» заявки — ссылка только
для маршрута, поэтому внутренности из неё убраны.

## 2.24. Карта-превью Viber: режим строки «Точка»

Карта под заявкой в Viber — это предпросмотр ссылки, который Viber рисует
САМ для любой кликабельной ссылки на Яндекс.Карты; у отправителя нет
флага «без предпросмотра» (в отличие от Telegram). Кликабельная ссылка
и отсутствие карточки в Viber взаимно исключают друг друга.

Поэтому в «Настройках → Сообщение» добавлен переключатель
«Строка „Точка“ в заявке»:
* **0 (по умолчанию) «координаты»** — в заявку попадает `53.86420, 27.55970`
  (или адрес текстом, если координаты не нашлись): одна строка, ссылки нет —
  Viber не рисует карту;
* **1 «ссылка»** — прежнее поведение: кликабельная ссылка и карта-превью;
* **2 «не добавлять»** — строки «Точка» в заявке нет вообще.
Компас в форме и маршрут в Яндекс.Навигаторе работают во всех режимах.

## 2.25. Кликабельная «Точка» сразу в Яндекс.Навигатор

Добавлен режим строки «Точка», который делает её кликабельной в Viber и
открывает Яндекс.Навигатор с подставленными координатами: ссылка вида
`https://yandex.ru/maps/?mode=routes&ll=LON,LAT&pt=LON,LAT&z=17` —
домен перехватывается Навигатором, режим routes сразу ставит координаты
целью маршрута. Если координат нет — маршрутная ссылка по адресу
(`?mode=routes&text=ул.+Казинца+83а,+Минск`).

Режимы «Точка» в «Настройках → Сообщение» теперь:
0. координаты текстом (компактно, без карты, не кликабельно);
1. ссылка на Яндекс.Карты (кликабельно, карта-превью в Viber);
2. **ссылка в Яндекс.Навигатор (по умолчанию)** — кликабельно, маршрут
   с координатами; Viber рисует карту-превью (плата за кликабельность);
3. не добавлять строку «Точка».

У получателя без Навигатора ссылка откроет Яндекс.Карты/браузер с той же
точкой — маршрут строится и там.

## 2.26. Починки: ввод в «К кому обращаться» и живучесть авто-вставки

1. **Буквы не вводились в текстовые поля** (контакт, адрес): очистка
   «только цифры и +» из v2.22 ошибочно применялась ко ВСЕМ текстовым
   полям, а не только к телефону. Теперь ограничение цифр действует
   исключительно на поле телефона; прочие поля принимают любой текст.
2. **Авто-вставка переставала срабатывать** (Viber обновился / MIUI убил
   службу):
   * поиск поля ввода ловит теперь подклассы EditText и кастомные
     редактируемые узлы Viber (не только точный android.widget.EditText);
   * кнопка отправки ищется по описанию, тексту И идентификатору ресурса;
   * окно авто-вставки продлено с 15 до 30 секунд;
   * если служба включена в настройках, но процесс службы мёртв, приложение
     показывает ДИАЛОГ «Служба авто-вставки не запущена» с кнопкой в
     спецвозможности (выключить/включить службу) вместо тихого отказа.
   Рекомендация для MIUI: настройки → приложения → ViberLead → «Автозапуск»
   включить; в недавних приложениях задать «Не закрывать» (замок), чтобы
   система не убивала службу.

## 2.27. Черновик формы до отправки + диагностика авто-вставки

1. **Форма больше не очищается при сворачивании/возврате.** Введённые
   значения живут до отправки: в памяти при pause/resume, черновиком в
   настройках при смерти процесса (восстанавливаются при запуске).
   Очистка происходит ТОЛЬКО после ушедшей отправки или кнопкой
   «Очистить форму». Пересборка формы при возврате — только если изменился
   конфиг полей (значения при этом сохраняются).
2. **Авто-вставка: диагностика и усиление.**
   * обход окна расширен до 1500 узлов, запасной кандидат — узел с hint;
   * в «Настройках → Авто-вставка» появилась строка «Диагностика»:
     последнее состояние цикла («взвод…», «вставлено…», «вставлено и
     отправлено…», «поле не найдено: узлов N, классы …»);
   * тот же статус попадает в диалог «Служба не запущена»;
   * если авто-вставка не сработает — скриншот строки диагностики
     показывает точную причину (мертва служба или Viber прячет поле).

## 2. Как устроена отправка (4 режима)

Режим выбирается: **Настройки → «Способ отправки»**.

| Режим | Что делает | Когда использовать |
|---|---|---|
| **Авто (по умолчанию)** | Пробует Viber API; если токена нет или API вернул ошибку — открывает Viber с готовым текстом | Универсальный |
| **Только Viber API** | `send_message` / `broadcast_message` через REST API | Есть токен Public Account |
| **Только открыть Viber** | Формирует текст и открывает Viber (текст подставлен в поле ввода) | Нет токена; заявки в обычную группу/чат |
| **Webhook** | POST JSON на ваш URL; при ошибке — резерв через Viber | n8n / Make / Zapier / свой бэкенд |

### Режим API: где взять токен и куда придёт заявка

1. Создайте **Public Account (Business)** в Viber: [partners.viber.com](https://partners.viber.com) →
   в админ-панели аккаунта **Info → Token** (строка вида `4f3a1c2d-...`).
2. Вставьте токен: **Настройки → «Viber API» → Токен**. Кнопка
   **«Проверить токен»** вызовет `get_account_info` и покажет имя аккаунта.
3. Куда доставляется сообщение:
   - если заполнено **«ID получателя»** — метод `send_message` этому пользователю
     (он должен быть подписан на ваш аккаунт);
   - если пусто — метод `broadcast_message`: всем подписчикам аккаунта
     или списку из поля **«broadcast_list»** (id через запятую).

> ⚠️ **Про «группу»:** Viber REST API не умеет писать в произвольные групповые чаты
> по номеру телефона — только подписчикам вашего Public Account (или в чат с
> бизнес-ботом). Поэтому для обычной группы Viber предусмотрен режим
> «Открыть Viber»: приложение подставляет весь текст заявки в поле ввода чата,
> остаётся нажать «Отправить». Укажите в настройках **«URI чата»**
> (`viber://pa?chatURI=имя_аккаунта`) или **телефон** (`viber://contact?number=+375…`),
> чтобы открывался сразу нужный чат.

Если Viber на устройстве не установлен — приложение покажет текст заявки и
предложит «Поделиться» (любой мессенджер) или скопировать в буфер.

### Режим webhook

**Настройки → Webhook → URL** (например, `https://n8n.example.com/webhook/lead`).
Полезная нагрузка (POST, `Content-Type: application/json`):

```json
{
  "company": "Название компании",
  "text": "Готовый текст заявки (как в Viber)",
  "datetime": "08.09.2026 14:35:12",
  "device": "Xiaomi Redmi Note 12 (Android 13)",
  "fields": { "name": "Иван", "phone": "+375291234567", "service": "Замер" }
}
```

Поле «Секретный заголовок» уходит заголовком `X-Auth-Token` — для проверки
подлинности на вашей стороне. Из n8n/Make заявку можно переслать куда угодно,
в том числе в группу Viber через Viber-интеграцию или Telegram-бот.

## 3. Настройка полей формы (без пересборки APK)

**Настройки → «Поля формы»** — JSON-массив. Кнопки «Вставить пример» и
«Вернуть поля по умолчанию» (читается из `app/src/main/assets/fields.json`).

Пример одного поля:

```json
{
  "key": "phone",
  "label": "Телефон",
  "type": "phone",
  "required": true,
  "hint": "+375 (__) ___-__-__"
}
```

| Свойство | Значение |
|---|---|
| `key` | Идентификатор для шаблона (`{key}`); обязателен |
| `label` | Подпись над полем |
| `type` | `text`, `phone`, `email`, `number`, `multiline`, `select`, `multiselect` (чекбоксы), `date`, `checkbox`, `org` (живой поиск по базе), `address` (поле + 🧭 маршрут) |
| `orgMap` | `address` / `contact` / `phone` — куда подставлять значение из карточки организации (по умолчанию выводится из ключа: `address…`, `contact…`, `org_phone`) |
| `required` | `true` — поле обязательно (подсветится красным при пустом) |
| `hint` | Подсказка в поле |
| `options` | Массив строк для `select` |
| `defaultValue` | Значение по умолчанию |
| `prefill` | `device` — модель устройства, `datetime`, `date` — автоподстановка |

Введённые значения запоминаются между заявками (удобно для_repeat_-заявок с
одного устройства), кнопка «Очистить форму» сбрасывает их.

## 4. Шаблон сообщения

**Настройки → «Шаблон сообщения»** (пусто = шаблон из
`assets/message_template.txt`, а если и его нет — генерируется по полям).
Кнопка **«Предпросмотр»** показывает результат с тестовыми значениями.

Плейсхолдеры:

- `{key_поля}` — значение поля формы (`{name}`, `{phone}`, …)
- `{label:key}` — «Метка: значение»; строка убирается целиком, если значение пустое
- `{company}` — название компании из настроек (попадает и в шапку приложения)
- `{datetime}`, `{date_now}`, `{time}` — дата/время отправки
- `{device}` — модель устройства отправителя
- `{address_link}` — ссылка на точку Яндекс.Карт/Навигатора для адреса заявки
  (пустая строка и её строка убираются, если адреса нет)

Строки шаблона, где остались только пустые плейсхолдеры, автоматически
удаляются — в Viber не улетают пустые «Город:».

## 6. Сборка из исходников

### Вариант А. Android Studio / Gradle (рекомендуется на обычном ПК)

```bash
# укажите путь к SDK, если переменная ANDROID_HOME не задана
echo "sdk.dir=/путь/к/android-sdk" > local.properties
./gradlew :app:assembleRelease        # или gradle :app:assembleRelease
# результат: app/build/outputs/apk/release/app-release.apk
```

Требования: JDK 17+, Android SDK (platform 34, build-tools 34), Gradle 8.7
(обёртка настроена в `gradle/wrapper/`). Keystore для подписи уже лежит в
`keystore/viberlead.jks` (пароли `viberlead` / `viberlead`); без него сборка
автоматически подпишется debug-ключом. **Для публикации в Google Play создайте
свой keystore** и поправьте `app/build.gradle → signingConfigs.release`.

В `gradle.properties` включён экономный режим ОЗУ (сборка проходила на машине
с 1.9 ГБ RAM). На мощном ПК уберите ограничения `org.gradle.jvmargs`.

### Вариант Б. Скрипт без Gradle (мало ОЗУ, CI, сервер)

```bash
export JAVA_HOME=/путь/к/jdk-17+
export ANDROID_HOME=/путь/к/android-sdk   # нужны build-tools;34.0.0 и platforms;android-34
bash scripts/build-apk.sh
# результат: dist/viberlead-release.apk
```

Скрипт последовательно вызывает `aapt2 compile → aapt2 link → javac → d8 →
zipalign → apksigner` (keystore создаётся сам через `scripts/make-keystore.sh`).

## 9. Частые вопросы

**Почему API возвращает status=8?** Получатель не подписан на ваш Public Account
или id указан неверно. Для рассылки используйте `broadcast_message` (пустое поле
«ID получателя»).

**status=2 / 13?** Неверный токен или токен от другого аккаунта.

**Открывается не тот чат?** Укажите точный URI в «Настройки → Открытие Viber →
URI чата» (например, `viber://pa?chatURI=mycompany`) или номер телефона.

**Хочу, чтобы заявки падали в группу без нажатий.** Варианты: (а) подписать
участников группы на ваш Public Account и слать `broadcast_message`;
(б) режим webhook → ваш сервер/n8n пересылает в группу через бота;
(в) держать телефон-приёмник с открытым чатом и режимом «Открыть Viber».

**Данные настроек хранятся локально** (SharedPreferences приложения) и не
передаются третьим сторонам — только напрямую в Viber/на ваш webhook.
